# 01 The accessibility settings model and `a11y.ini`

Status: resolved (2026-10-20)
Type: task

`.scratch/accessibility-settings/spec.md`, "Storage" and "The model". The cue settings model (`value_model`, `value_file`, `cue_settings`) becomes the fork's whole accessibility settings model, kept in `a11y.ini` and written by the game one line at a time.

## Machinery

- **The file.** `a11y.ini` in the base port's settings folder, written fresh with defaults and descriptions when missing. `MELEE_A11Y_SETTINGS` replaces `MELEE_A11Y_CUE_SETTINGS`, with the same meaning for an empty value (defaults, no file). `a11y-cues.ini` is no longer read. `drive.py` and `drive_net.py` set the new variable.
- **The line edit.** A value set through the model is saved by replacing the value on its key's line, or appending the line under its group heading when the key is missing. Comments, order, other lines and unknown keys stay as written. The write goes through a temporary file and a rename. Spec open question 1: the poll that follows the game's own write finds nothing changed and says nothing.
- **`shown`.** A flag where a value is registered. The model lists the shown values in registration order, and for each cue registered with `add_cue` it lists the cue's switch, its volume and a Preview row (an action carrying the cue's id), so a front end needs no list of its own. Mark the values the spec's "Rows" table names, and register `position_cues.pan_to_camera` after the opponent's position cue.
- **Polling in the menus.** The file is also polled while the launcher or the port menu is open, from the hooks the fork already has there (`pc_a11y_launcher_frame`, `pc_a11y_port_menu_frame`).
- Names in code follow `CONTEXT.md`: accessibility settings, tuning value.

## Done when

- The `cue_settings` unit tests pass under the new names, with new cases for: the line edit keeping comments, order, other lines and unknown keys; a missing key appended under its group; the game's own write polled back silently; the shown list with each cue's three rows.
- A drive run with `MELEE_A11Y_SETTINGS` naming a file in the run's folder writes `a11y.ini` with every value, and a hand edit made while the launcher is open (`drive.py --launcher`) is picked up there.
- The `verify` skill's quick and menus levels pass, and `python tools/check_style.py`.
- `docs/a11y/cues.md`, "Cue settings", and the `verify` skill name `a11y.ini` and `MELEE_A11Y_SETTINGS`. CLAUDE.md's match cues status line names the new file.

## Comments

### 2026-10-20, implementation (agent)

Implemented; the cue values are now the accessibility settings, kept in `a11y.ini`, saved one line at a time and listed as the menus' rows.

- **Where things live.** `accessibility_settings.hpp/.cpp`: `AccessibilitySettings`, owning the `ValueModel` and its `ValueFile`, with `load`, `poll`, `set`, `shown` and one listener. `hooks.cpp` creates it in `pc_a11y_init` before the cue system, so it outlives a closed engine, locates the file (`settings_file_path`: `MELEE_A11Y_SETTINGS`, or `a11y.ini` in `pc_get_pref_path`), loads it once every feature has registered, and points the listener at `CueSystem::settings_changed`. `CueSystem` no longer owns the model or the file; it registers the cues' values into the shared model and still polls on each match tick. `Config::cue_settings` became `Config::settings_file`.
- **The line edit.** `ValueModel::edit_text` replaces the value on the key's last line (the one `read_text` takes), keeping the key as written, its spacing, a trailing comment and the line's ending; a missing key goes with its description at the end of its group, before the blank lines and the next group's heading, or with its heading at the end when the heading is missing too. New lines take `\r\n` when the text's first line has it. `ValueFile::set` saves through `a11y.ini.tmp` and a rename (`std::filesystem::rename`, as `launcher.cfg`'s save does), and logs `saved <key> = <value>`.
- **Spec open question 1: the poll after the game's own write says nothing.** The save leaves the file's stamp and text as the poll last saw them, so the next poll compares equal and reads nothing; even with a coarse stamp it would read the same text and stop there. A second ordering came out of it: `set` reads the file first, whatever the poll's interval, so a hand edit saved within half a second before a menu change is applied and kept rather than overwritten by the save. Both are unit tests.
- **`shown`.** A `shown` member on `SwitchSpec`, `NumberSpec` and `NamedValue`. Actions are a second kind of row, `NamedAction` (registered with `ValueGroup::add_action`, never in the file). `ValueModel::shown()` returns `ShownRow`s in registration order, each holding a value or an action. `add_cue` gives each cue its switch and volume, both shown, then the action `<cue>.preview` labelled "Preview gap warning", whose `group` is the cue's id, then the boost as a tuning value. Shown now: `cues.on`, `cues.volume`, each cue's three rows, `position_cues.pan_to_camera` and `ledge_warning.distance`. `position_cues` is registered after the opponent's position cue, so the file's group order changed too.
- **Labels and help from the spec's Rows table**, set where the values are registered: "Position cues follow the camera" and "Ledge warning distance" with the spec's help texts, which are also the file's comments now (the ledge distance's old note on a dash's length went). Preview's help is my own first proposal: "Plays a short sample of the gap warning, as it sounds in a match."
- **Polling in the menus.** `pc_a11y_launcher_frame` polls every frame, `pc_a11y_port_menu_frame` while the menu is open, and `pc_a11y_scene_entered` now polls from the hooks whether or not cues are open (the cue system only records the error count before it).
- **Drivers.** `drive.py` (and `drive_net.py` through it) set `MELEE_A11Y_SETTINGS` to the run's own `<out>.settings/a11y.ini` unless the environment names a non-empty file, which an empty value used to be dropped for.
- **Wording in logs and speech.** The log prefix is `[a11y] accessibility settings:`, the spoken error "Accessibility settings, line 2 not understood.", an unknown key `<key> is not a known key; kept in the file` ("setting" now means a shown value), and with no file a change logs `<key> = <value>, not saved: no file`.
- **Tests.** The suite is `accessibility_settings` now (`test_accessibility_settings.cpp`, the old `cue_settings` cases kept), with new cases: a menu change edits only its line among comments, odd spacing, other lines and an unknown key, and holds the range; line endings, the last of two lines and empty values; a missing key added under its group, in text and in the file after the player deleted the line; the game's own write polled back silently; a hand edit not yet polled surviving a menu change; the shown rows with each cue's three; the listener told of menu changes and hand edits, and the settings without a file. `match_cues` checks the real registration's rows against the spec's table, less issue 02's switches.
- **Verification**, quick, menus and online levels, all with `MELEE_A11Y_CUES=1`: build with the "Rollback sections" line; style; unit tests, all passing but `launcher_data` (known); a bounded `title` run writing `a11y.ini`; the seven match scripts and the twenty menu scripts in one `run_level.py` call, 27 of 27; the four online runs, 4 of 4. Two hand checks from a Python script driving `drive.py` and editing the run's `a11y.ini` while it waited: on the launcher (`--launcher --muted`) the file was written with all 27 keys and `cues.volume = 40` and `ledge_warning.distance = 41` were logged about half a second after the edit, with the launcher still open; the same in the port menu opened from the main menu.
- **Docs.** `docs/a11y/cues.md`: "Cue settings" became "Accessibility settings", with "Settings and tuning values", "Saving a menu's change" and the menus' polling; the lifecycle bullet says who owns what. The `verify` skill: `a11y.ini`, `MELEE_A11Y_SETTINGS`, the new log lines, the suite's name, and how to check a hand edit mid-run. CLAUDE.md's match cues line names `a11y.ini`.
- **For issue 02.** The cues register their values only when `CueSystem::open` succeeds, so with cues off (or the output failing) the file and the shown list lack every cue value; making the engine always open, as the spec decides, fixes both. The switches register their group in `s_settings->model()` before `CueSystem::open`, since group order is creation order and rows are registration order. `speech.cpp:config_from_environment` still reads the switches.
- **For issue 04.** A front end walks `AccessibilitySettings::shown()` and needs no list of its own: for a row with `value`, a switch when `value->kind == ValueKind::toggle`, otherwise a slider over `min`, `max` and `step` with `unit`; `label` is the row's name and `description` its help. A row with `action` is a button; for now every action is a cue's Preview, to call with `action->group`. Changes go through `AccessibilitySettings::set(named, value, now)`, which saves and tells the listener; the instance is `s_settings` in `hooks.cpp`, so the front end needs it passed in or a getter.
- **Left open.** The Preview help text and the shortened ledge distance help, for the play test.
