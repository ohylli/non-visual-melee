# 02 The voices: rendering, playing and queueing

Status: resolved (2026-10-28)
Type: task

Spec: `.scratch/voices/spec.md`. Read it first, with ADR-0008, ADR-0005, `docs/a11y/speech.md` and `docs/a11y/cues.md`. Prior art: grimdark's `src/voice.cpp` and `src/tts_onecore.cpp` (`C:\Users\ottoh\koodi\grimdark`).

## What to build

- **Prism v0.18.2 first.** Answer the spec's open questions 1 and 2 before building on them: render a line with `prism_backend_speak_to_memory` on a OneCore instance from a worker thread, with a rate set, and note the apartment it needed. Record the answers in `docs/a11y/speech.md`.
- **The bridge.** `screen_reader_bridge` gains the voices' side: create a OneCore instance, list its voices (display name and language), set voice and rate, render a line to samples. It stays the only file that touches Prism. The fake renders known samples.
- **The worker.** One thread owns both instances, created once speech is first on and kept for the run. It renders, evens each line out to a fixed peak (a tuning value), converts it to mono at the cue engine's rate, and hands it to the cue engine.
- **The cue engine's new voice.** One per speaking voice: plays a buffer handed to it at run time, once, with the start and stop ramps, centred. Its chain is master volume × the voice's volume, not the cue volume or any cue switch.
- **Speech.** An announce call for a voice, with the line's subject. The queueing rules: a playing line about the same subject is cut with the stop ramp and the new one plays at once; a waiting one is replaced in place; otherwise the line queues. The two voices are independent of each other and of the screen reader.
- **Switches and the port menu.** Under Speech and Accessibility: off, voice lines are logged `(off)`. Turning either off, or opening the port menu, lets the playing line finish and drops the waiting ones. `MELEE_A11Y_SCREEN_READER=0`: decide open question 5 and record it.
- **Defaults.** Your voice the first voice whose name contains "Zira", the opponents' voice "Mark", else the Windows default voice. The rows, the fallbacks' announcements and saving the choice are issue 03's.
- **A developer switch** in the manner of `MELEE_A11Y_CUE_PREVIEW`, environment only, that has each voice say a line from the first frame, so this issue can be heard and checked through the cue dump before the rows exist.
- **The speech log.** Every voice line names its voice, with the `(off)` and muted marks; a line cut off or dropped is logged.
- **Measure** open question 3 (render time, short and long lines) and decide on the cache.

## Comments

### 2026-10-28, implementation (agent)

Implemented; no feature speaks with the voices yet, so they are heard only through the developer preview.

- **Where things live.** `screen_reader_bridge.hpp/.cpp`: `VoiceBridge` (`open`, `close`, `voices`, `default_voice`, `set_voice`, `set_rate`, `render`), `VoiceInfo`, `RenderedLine`, `make_voice_bridge`; still the only file that touches Prism. `voices.hpp/.cpp`: `Voices`, the worker, the queue, `find_voice`, `sort_voices`, `even_out` (mono, miniaudio's linear resampler to 48 kHz, peak to `kVoicePeak`). `speech.hpp/.cpp`: `Voice`, `Subject`, `kPreviewSubject`, the `VoiceLines` interface speech holds, `Speech::announce_voice` and `attach_voices`; speech starts the voices with the screen reader and has them drop their waiting lines when it goes off. `cue_engine.hpp/.cpp`: `VoiceMode::once` with `CueEngine::play`. `hooks.cpp`: `s_voices`, made after the cue system and attached before the switches turn speech on, its frame from the launcher's and the port menu's frame hooks, reset before the cue system. No new hooks.
- **Open question 1, Prism v0.18.2.** As v0.14.4: the whole line, one callback on the calling thread, mono 16 kHz for every voice here, silence trimmed. Rate applies to rendered lines (one line: 2.5 s at 0.5, 1.5 s at 0.8, 6.5 s at 0.2). New in v0.18.2: OneCore's pitch is set (`AudioPitch`), so the spec's "Pitch" exclusion could be revisited. Read from the v0.18.2 source (`git -C ../prism show v0.18.2:source/backends/onecore.cpp`, tags fetched) and an experiment program against the pinned DLL.
- **Open question 2, COM.** `prism_init` still makes the calling thread a single-threaded apartment, and OneCore runs its blocking WinRT calls on the thread pool from one. The worker calls `prism_init` itself, a context apart from the screen reader's, and creates both instances there; nothing more was needed. Two instances also rendered at once from two threads.
- **Open question 3, render time.** Opening the two instances: about 330 ms, on the worker. Short line: about 5 ms warm, 15 to 30 ms for a voice's first; a long one (2.5 s of speech): 15 to 45 ms. In the game, said to handed to the engine: 33 ms (two frame boundaries), plus the device's buffer. No cache: each line is rendered as it is queued, enough rendering ahead. Every `plays` log line carries its render time and wait for the play test.
- **Open question 5, the screen reader switch.** `MELEE_A11Y_SCREEN_READER=0` leaves the voices rendering and playing, logged unmarked: they reach the cue engine, never the screen reader, and agent runs send that to SDL's dummy driver, so a driven run checks them through the log and the dump without a sound. Prism is started on the worker for them alone. There is no `(muted)` mark for a voice's line.
- **A finding: `prism_shutdown` hangs at exit.** Called on the worker while the game exits (from the atexit handler that runs `pc_a11y_shutdown`), it never returned once a OneCore instance had rendered; freeing the instances, or `CoUninitialize` alone, returned. `PrismVoiceBridge::close` frees the instances and leaves the context to the process's end. The screen reader's own bridge may meet the same if Prism ever picks OneCore for it at exit (no screen reader running); untested.
- **The defaults.** Your voice wants "Zira", the opponents' voice "Mark"; `find_voice` takes the voice of that display name ignoring case, else the first whose name holds the text, else the Windows default voice, in the list sorted by language then name, the same on the worker and the game thread. The default voice here is Microsoft George (en-GB); Zira and Mark are installed, so is Microsoft Heidi (fi-FI) for question 6.
- **Choices beyond the issue.** A cutting line plays as soon as it is rendered, so the old line keeps sounding for the few milliseconds of the render instead of a gap. A line said while the port menu is open plays (it is where Preview will be pressed); only the opening drops the waiting lines. A line that renders to silence is dropped (`no sound rendered`). The worker never logs (the port's logger is not thread-safe); the game thread logs its news each frame.
- **The developer switch.** `MELEE_A11Y_VOICE_PREVIEW=1`: once the voices are ready, your voice says "Your voice", then, a pause after it ends, the opponents' voice "Opponents' voice", through speech and its log.
